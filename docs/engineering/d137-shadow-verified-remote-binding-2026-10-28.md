# D137: Bind Shadow Local Index to verified immutable Destination Git content

Date: 2026-10-28. Re-encryption Wizard remains **preview-only**, and the public release gate remains **blocked**.

## Scope

`verifyV4ReencryptionShadowAgainstDestination` in `src/lib/v4/reencryption-shadow-remote-binding.ts` performs a read-only, uncommitted **content binding** between the D134 staged Shadow Local Index and an independently verified immutable Destination Git commit. It invokes the existing D83 `verifyV4ReencryptionDestinationExactCommit()` directly, not a caller-provided success callback or untrusted report. D83 performs Git repository identity and branch-ref readbacks, zero-parent orphan commit/tree validation, exact blob checks, exact committed plaintext config plus AES-GCM authenticated encrypted HEAD/shards under the new passphrase, every expected file record, every uploaded-object receipt, all plaintext SHA-256 and size checks, and a final Git ref/repository reread.

D137 pins the adapter, lease and durability assertions, immutable commit SHA, source tree SHA, plan, remote configs, ciphertext receipts, passphrase identity and GitHub client methods. It reads the complete Shadow before the remote proof, derives exact verified record expectations from that Shadow (so separately supplied unverified `expectedRecords` cannot mask an altered cache), and rejects duplicate path IDs and any dirty/deleted local record. The D83 verifier now accepts an **optional** `expectedLocalIndexHead` from D137 and compares the decrypted Git HEAD device ID, epoch, generation and complete shard-hash mapping to the Shadow header. D137 reads Shadow again after the remote proof and requires byte-equivalent full in-memory metadata/records. Any mismatch or mutation fails closed. Existing D83 callers without that optional expectation retain their previous verification contract.

On success, D137 returns `shadow-matches-verified-destination-uncommitted` with only repository ID, commit SHA and verified file count. It never returns logical paths, file plaintext, passphrases, tokens or keyring material. It explicitly returns `localCutoverAuthorized:false`, `resumeSyncAuthorized:false`, `remoteWritesAuthorized:false`, and `oldPassphraseCleanupAuthorized:false`.

## Tests and security boundaries

Added real cryptographic verifier exercises to `tests/v4/reencryption-destination-exact-commit.test.ts`. The fixture prepares AES-GCM remote metadata plus content (including Unicode and chunked objects) with real production codec and Git SHA-1 object identities, backed by simulated GitHub GET responses. Tests establish success without any Shadow writes or reporting plaintext; rejection of a forged Shadow record with recomputed local digest; rejection of self-consistent but wrong local HEAD generation; moved Destination Git ref; concurrent change of Shadow during remote blob fetch; a swapped GitHub reader method; changed caller input during lease; and missing Shadow. Original D83 cases remain.

**Local verification:** Focused D83+D137 12/12 PASS. Full Fast 987/987, Recovery 85/85, Resource 11/11, Feasibility 136/136, Maximum Strict TypeScript, production build, GitHub E2E compile-only, release validations and 100 MB reference-SHA cryptographic soak PASS. The first 10-round Fast repeat stopped at round 9 because an unrelated D15 Windows junction fault-injection failed to finish swapping its test directory (986/987 on that round). Focused D15 14/14 PASS. The test now prints the rollback error when the swap misses; no assertion was weakened. A new exact-source 10-round Fast repeat **10×987/987 PASS, exit 0**. This does not erase the earlier intermittent D15 test-injection finding.

**Trust limit:** Remote verification depends on the injected GitHub client accurately representing an authenticated GitHub API connection; mocked GET responses in unit tests are **not** a live GitHub proof. This is not wired into D136, Wizard or automatic Sync. It verifies the point-in-time consistency of one Shadow with verified remote content, but does **not** produce durable commit evidence, authenticate the D135 local Intent, commit Settings/SecretStorage/selected Index, establish OS-wide Vault quiescence, provide power-loss directory persistence, authorize restart/resume, or trigger old-passphrase cleanup. D136 local WAL observations and D137 remote content observations still require a separately proven cross-surface transaction/commit coordinator before any cutover.

Windows Node-only WAL directory fsync `EPERM` remains a blocker for strict power-loss guarantees. No Native Helper, GitHub Actions, branch deletions, force pushes, actual user Vault writes or release-gate changes were introduced.
