## Explicit architecture decision remains necessary

Historical implementation eagerly forwarded local and remote conflict bytes before resolving the dialog; the current V4 production path deliberately keeps conflicts **metadata-first**, avoiding remote content fetch when choosing Use local and preserving pre-mutation conflict totals/snapshot safety. The historical review permits up to 16 MiB UTF-8 per side, while current unattended three-way merge is limited to 2 MiB by `V4_MAX_MERGE_BYTES`. Blindly restoring the old UI would trade away optimized/verified semantics, possibly download unnecessary content, or allow stale manual merges while notes remain open.

Proposed safe integrated path subject to user approval: keep metadata-first default; when user explicitly chooses **Review lines**, fetch local snapshot and commit-pinned authenticated remote content under resource bounds; enforce fresh local snapshot and open-editor protection again immediately before staging/publishing the user-approved merged result. Restrict manual review size by an explicitly approved budget and fall back to Keep both/cancel without loss. Preserve queued Sync settings identity and original conflict policy on in-flight runs. This requires new negative/cancellation/source-drift/overwrite tests and native Obsidian UI tests before wiring the new modal. Do not silently choose 2 MiB vs 16 MiB limit or alter fail-closed behavior.

Do not merge GitHub Actions, experimental Native OS Helper binaries, unsupported legacy files, or unreviewed old commits. Preserve all historical worktrees, root Zed WIP and disposable GitHub branch cleanup evidence.
