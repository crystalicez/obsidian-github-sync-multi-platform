# V4 Performance and Resource Qualification Methodology

Date: 2026-07-30

Performance claims must state the workload, platform, measurement method, and whether the data is model, automated virtual-stream evidence, or physical-device evidence.

## Required workloads

1. unchanged 10k-file metadata scan,
2. one changed file,
3. 1,000 small changed files,
4. each conflict policy/action path,
5. bounded pack batch,
6. 512 MiB virtual large-file path,
7. 2 GiB cryptographic virtual soak,
8. 5 GiB cryptographic virtual soak,
9. Windows physical 5 GiB encrypted round trip when qualifying that claim,
10. Android physical large-file round trip only after bounded I/O capability exists.

## Metrics

Record, where applicable:

- elapsed wall time,
- logical bytes,
- selected part size / part count,
- peak resident/private-working-set bytes and measurement method,
- transport transient-byte peak,
- request and mutation counts,
- request/response bytes,
- retries, unknown outcomes, cooldown and pacing time,
- staging bytes / required free-space headroom,
- recovery time and number of resumed mutations,
- final SHA-256 equality.

Do not compare browser JS heap, Node RSS, and Windows private working set as if they were the same metric.

## Automated tiers

```bash
pnpm test
pnpm test:repeat
pnpm test:recovery
pnpm test:resource
pnpm test:feasibility
```

`tests/resource/v4-resource-regression.test.ts` covers threshold-1, threshold, threshold+1, and a 512 MiB virtual source without logical-size allocation.

`tests/soak/v4-5gib-stream.test.ts` processes generated bytes cryptographically. The package soak command enables the full test:

```bash
pnpm test:soak
```

For a quick harness check only (not a 2/5 GiB qualification):

```bash
node scripts/run-soak.mjs --bytes=67108864
```

The soak compares the plugin incremental SHA-256 implementation with Node's SHA-256 in the same generated-stream pass and reports RSS delta. It reuses one bounded chunk; it never creates a 2 GiB/5 GiB logical `Uint8Array`.

## Baseline JSON rules

`tests/baselines/v4/windows.json` and `android.json` are evidence records, not aspirational targets.

- `null` means not measured.
- `pending` means a required measurement has not been run.
- `platform-capability-fail` is valid when the implementation intentionally refuses an unsafe path.
- Never copy a model number into a physical measurement field.
- Update source commit/archive hash together with new measurements.

## Task 15 nearest-equivalent development baseline

These numbers were captured in the isolated Linux/Node 22.16.0 implementation environment on 2026-07-30. They are useful regression baselines only; they are **not** Windows or Android device claims.

| Workload | Result |
| --- | ---: |
| unchanged 10k planner state, median of 9 | 5.81 ms |
| one-file change within 10k, median of 9 | 4.78 ms |
| 1,000 small creates, median of 9 | 0.36 ms |
| four conflict-policy decisions, median of 9 | 0.045 ms |
| 500-entry pack grouping, median of 9 | 51.32 ms |
| 512 MiB virtual source preparation | 2.80 ms, 11 objects, source unopened |
| crash-matrix suite | 7/7 in 0.63 s process wall time |
| 2 GiB cryptographic generated stream | 13.35 s test time, digest matched Node SHA-256, 43 parts, ~1.4 MiB measured RSS delta inside the test |
| 5 GiB cryptographic generated stream | 33.27 s test time, digest matched Node SHA-256, 107 parts, ~1.4 MiB measured RSS delta inside the test |

The 5 GiB soak initially exposed an allocation-rate defect in the incremental SHA implementation: it created a `Uint8Array.subarray()` view for every 64-byte compression block. Task 15 added a regression test and changed the compressor to accept an offset directly. The hash algorithm and digest output are unchanged; the qualification soak then completed without the previous GC cliff.

The full soak runner intentionally launches 2 GiB and 5 GiB cases in separate processes. This makes each result independently observable and prevents one completed soak from being obscured by a later process failure or environment limit.

## Official Windows automated evidence

The Task 15 Windows automated gate is recorded as passed in `tests/baselines/v4/windows.json`: build; fast `345/345`; repeat `345/345 × 10`; recovery `30/30`; resource `11/11`; feasibility `6/6`; package validation; and the separate 2 GiB + 5 GiB cryptographic virtual soak. No Windows physical timing, process-memory value, request count, mutation count, or 5 GiB round-trip SHA is inferred from those automated results.
