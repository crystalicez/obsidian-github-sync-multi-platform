# D389 — Installed Obsidian lease revocation blocks a live WAL writer (PASS; release BLOCKED)

Date: 2026-11-11 (Asia/Bangkok). Inherited D87 audit worktree only. No commit, push, merge, GitHub Actions, real user Vault, live GitHub API call, branch or Settings/Index Cutover. This is **NOT** installed end-to-end Re-encryption migration, OS-wide exclusive lease proof, power-cut durability, or release authorization.

## Objective

Extend the D377 *actual installed Windows Obsidian* synthetic Vault + plugin WAL writer proof to cover a one-way initiating lease that becomes unavailable **after** the installed Runtime has armed its persisted Sync Fence and authored an authenticated encrypted two-slot WAL through a live OS-exclusive writer. The real writer remains open while the test attempts to mutate a valid WAL slot and take a best-effort checkpoint. These must fail **because the initiating lease is revoked**, not merely because the target path is malformed or Obsidian is absent.

No change was made to `src/`, the installed Wizard, WAL policy or the release gate. The only runtime additions are inside the disposable test bundle and the invoking Node test runner:
- `scripts/run-obsidian-disposable-wal-authoring.mjs`: new explicitly selected `--revoke-lease-after-intent` scenario, retaining the existing default and `--kill-writer` scenarios. The renderer creates an owner-controlled **synthetic** lease callback and gives that same closure to the **production installed Runtime**. It successfully arms the persisted Sync Fence, opens `openNewReencryptionDesktopWalForArmedRun()`, and writes generations 1→2 (one pending Backup ref intent, zero verified remote refs). While the real writer's lock is still held, it revokes that callback, attempts a **valid** `slot-0.json` overwrite and `writer.assertBestEffortCheckpoint()`, and requires both rejections to come from the lease-specific sentinel error. This deliberately uses a valid slot pathname; an invalid filename could be refused independently and produce a false positive. It verifies the physical Vault's WAL directory file list and two encrypted slot SHA-256 hashes remain byte-identical, and normal Settings Save stays refused.
- `scripts/native-installed-wal-writer-probe.ts`: adds a test-only independent physical `DataAdapter.read` verification of both slot hashes. The test reads the complete Vault logical path `<configDir>/plugins/<pluginId>/reencryption-wal/<run-hash>`; the WAL writer's `journalRoot` is **relative to the plugin storage root**, not the Vault root. The first D389 run failed in this test-only path proof and removed the temporary Vault; fixing the test's logical path and changing the attempted write to a *valid* slot yielded a trustworthy proof. No Production defect or deployment regression was inferred from that initial failure.

After closing the original writer normally (not auto-reclaiming a stale lock), the runner kills its isolated Obsidian process, starts a **different installed Obsidian process** using the same synthetic Vault/profile, independently authenticates the exact two WAL slots and pending Backup intent, checks the persisted Sync Fence, confirms Settings Save and new WAL authoring are still denied, and verifies neither Sync Resume nor Cutover is authorized. The plugin has no GitHub token; the test makes **zero GitHub requests**. The runner removes only its own verified disposable test Vault/profile after both processes terminate. Process-loss `--kill-writer` variant intentionally preserves the stale lock for detection, does not automatically reclaim it.

## Remaining release blockers and next integration boundary

The installed synthetic test uses only a local revocable callback—not the user-initiated exclusive migration lease over a genuine authenticated Source Git commit and disk-backed initiating Vault parity. It creates only a pending **synthetic** Backup ref intent, not a real GitHub frozen Backup ref and staged Destination; actual GitHub continuity is independently covered by D378–D386 in disposable Node E2E, not yet joined to the installed Obsidian state machine. Actual Settings/SecretStorage/Selector/Index committed Cutover and restart-safety, two-device stale-client behavior, Windows/macOS/Linux platform scope and physical Android/iOS acceptance remain unfinished. Preserve best-effort Manual Recovery, two old/new passphrases, old Source and frozen Backup, 8 MiB new ciphertext-object policy and capability-gated Mobile initiation ≤32 MiB. Do not claim release readiness or enable Wizard Execute. Release gate `docs/release-gates/reencryption-wizard.json` stays `blocked` (six pending).
