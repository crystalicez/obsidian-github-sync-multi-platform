## Confirmed fail-first regressions (no real secrets)

1. Existing `migrateV4Secrets` accepted aliased token and passphrase secret IDs, potentially overwriting one type of secret with another. Original code had an explicit collision guard. **RED**: migration and normal save produced secret writes instead of rejecting aliases; duplicate IDs generated by ID factory were also unprotected.
2. On a synthetic second-write failure during legacy secret migration, `migrateV4Secrets` left the first saved secret replaced. Historical migration code snapshotted prior secret values and attempted rollback. **RED**: the original value was not restored.
3. `GitHubClient` accepted malformed owner/repo/branch coordinates at constructor time (e.g. `../another`, `feature//main`, `topic@{1}`), despite previously checked Git ref names. **RED**: invalid configuration did not throw.
4. `FastSync.loadSettings()` migrated secrets from malformed persisted settings before enforcing runtime type/branch/ignore-regex checks. **RED**: synthetic corrupted owner `../unsafe` did not block startup secret writes. `saveSettings()` changed runtime credential generation even when secret IDs were aliased and writing then failed. **RED**: generated unintended credential-change notifications ahead of validation.

## Guard restoration

- New `src/lib/github-config.ts` (historical stable GitHub owner/repository/Git-ref validation), called from `GitHubClient` constructor before client resource/scheduler setup. Valid nested branch `feature/rest-safe-8mib` is supported; rejected coordinates fail before network access.
- New `src/lib/plugin-settings-validation.ts` (historical runtime guard, adapted to maximum strict index-signature access) validates owner/repo/ref, ignore regex, known encryption/conflict modes, numeric bounds, secret-ID distinctness, optional booleans and string fields. Called **before any secret migration** in `FastSync.loadSettings`, and at the **start of** `FastSync.saveSettings`, before runtime generation invalidation/secret writes/reconfiguration. Existing defaults remain valid.
- `src/lib/v4/secrets.ts`: nonempty token/passphrase secret IDs must be distinct, checked before migration and save writes; generated ID alias rejected. Snapshot old secrets before migration writes; best-effort rollback every touched ID on failure, while preserving the original thrown error. No actual user secret contents are logged or exposed, and no changed ciphertext/key/wire representations.
- Explicitly **not** claiming transactional secret store on arbitrary OS storage failures; rollback is best-effort, and normal settings saves' two independent writes remain non-transactional. Do not alter encrypted protocol or Git CAS/retry/deletion/conflict semantics.
