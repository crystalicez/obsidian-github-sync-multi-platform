Production commit c12f494b1a32f5e44eff7a003306c52046f533dd; test/runner commit 0e3a07b494aef194062a9361d2fedf11b96a8e16 (same production). Both pushed on the audit branch.

After D519 persists Destination Settings, the currently hydrated passphrase/branch may be the new key/branch (or the new key may be missing). D520 discovers the historical Source and run from a bounded fence/locator restricted to the current repository and device; the hint is not authority. The original key is independently derived from authenticated frozen Backup, the WAL and staged SecretStorage receipt must match, and the encrypted Settings intent must authenticate the exact current persisted Source or Destination record, both Index digests, secret IDs and current owner. The existing Recovery command selects this path when the installed intent exists. A mixed Settings record or tampered intent cannot expose a repairable missing-slot report. Explicit repair verifies the Destination, exact refs and WAL under the same lease and rechecks the authenticated Settings intent before restoring only the missing staged ID. No settings rewrite, Index mutation, fence release, automatic Sync or old-key cleanup. The live hydrated passphrase is not changed by this recovery.
